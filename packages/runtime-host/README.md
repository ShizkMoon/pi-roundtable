# Runtime Host

This package is the only Pi SDK integration boundary. `RuntimeAdapter` is the domain-neutral contract that meeting orchestration consumes, but Pi is the product's only supported model runtime.

`PiRuntimeAdapter` is the implemented direct Pi SDK boundary. It creates one in-memory Pi session for one role, requires an exact provider/model plus a runtime-supplied API key, overrides the role System Prompt, disables default Skill discovery and loads only explicitly granted Skill paths, disables Pi's default tools unless the caller provides an explicit allowlist, registers tools discovered from explicitly approved MCP grants, normalizes Pi events, serializes lifecycle transitions, and keeps a bounded in-process command cache for idempotent retries. It does not persist credentials or expose raw Pi session records. When the Host grants delegation, it may add one controlled `spawn_subagent` tool; that tool is owned by Pi Roundtable rather than treated as an unrestricted Pi capability.

`McpClientManager` uses the official MCP TypeScript SDK for stdio, Streamable HTTP, and legacy SSE transports. It enforces single-flight bounded discovery/output, same-origin HTTPS or loopback-HTTP remote calls, an approved stdio-launcher set, credential references resolved only in memory, and deterministic tool names. Transports become manager-owned before connection starts, a failed or unexpected transport exit closes the whole manager, and returned tool closures retain only a clearable connection handle. Interactive `always` and first-use approval is implemented without exposing arguments or results in approval events. `subagent_required` MCP grants remain disabled until isolated tool execution is implemented. Every per-server tool allowlist is an exact filter: an empty list authorizes no tools, and approval of a call cannot expose or authorize an unlisted tool.

`LocalRoundtableHost` is the implemented in-memory meeting orchestrator. Its private `RuntimeGenerationOwner` fences one externally assigned generation, owns configuration/lease/stop lifecycle, and never allocates or increments generations. Its private `MeetingCommandRouter` owns the one deterministic queue shared by lifecycle cleanup, commands, configured-role restoration, and internal continuations. The Router hashes bounded canonical command input into fixed-size fingerprints, provides count-bounded idempotent receipts, checks generation and expected sequence fail-closed, and invokes Host-owned kind handlers without taking over meeting state or Pi sessions. `DefaultDiscussionOrchestrator` now owns the deterministic scheduler seam for agenda, floor priority, transition, interruption, turn, and observer budgets without owning adapters or event delivery. `SynchronousNormalizedEventWriter` owns the meeting-wide sequence, normalized protocol envelope, stop fence, and synchronous listener fan-out; persistence and stdio framing remain downstream concerns. `RoleSessionSupervisor` owns immutable role/generation/session tokens, registers adapters before startup, supplies a role-local abort scope, filters retained callbacks by current adapter identity, makes adapter stop single-flight, and attaches planner, observer, and SubAgent child resources to the parent role. Queued public turns, interruption handoffs, observer decisions, and SubAgent continuations carry the same exact session identity, so removing and recreating a role with the same public ID cannot inherit old work. `RoleContextAssembler` validates one frozen participant and composes two replaceable seams: the offline `ProviderCapabilityRegistry` resolves declared primary provider/model metadata, while `CapabilityResolver` maps only approved Skill/MCP grants and the exact built-in `provider.web_search` grant to executable resources. Generic grants and fallback routes remain non-executable, and dynamic agenda/message context stays in Host user turns. The role's Pi session, its internal MCP manager/provider transport, and its credential lease retire with the same resource scope. The meeting vault and each role lease own isolated mutable UTF-8 Buffers and synchronously overwrite them on stop, failed start, cancellation, meeting close, and terminal stdio cleanup. The Pi runtime uses a private in-memory credential store with global model configuration disabled, then deletes that store and closes transports without invoking the SDK's network-refreshing credential-removal path. JavaScript strings already handed to Pi, MCP, a child environment, or a managed client remain physically non-zeroizable and are released by disposal/dereferencing or OS process exit. A stop request immediately closes later lifecycle entry points, requests cancellation of in-flight role startup without waiting indefinitely for its startup Promise, and prevents queued continuations or late callbacks from writing afterward. The Host accepts public meeting commands, emits normalized public/private meeting events, routes tool approvals, performs the interruption handoff, and preserves meeting-wide floor, discussion, and event-order semantics. Each parent role may run at most two SubAgents, children cannot recurse or receive MCP tools, progress events contain counts rather than task/result text, and the result returns privately to that parent. `StdioRuntimeHost` exposes the orchestrator to the Windows application through bounded JSONL frames; a shutdown frame can preempt a stalled Host operation, EOF triggers suspend cleanup, stdout is protocol-only, and diagnostics use explicit error frames or stderr.

`provider.web_search` uses a replaceable provider seam and currently implements only the official OpenAI Responses web-search route. It requires an explicit role grant, a tool-calling model, and allowed workspace network policy; direct calls reuse the normal private approval flow, while SubAgents receive it only under `never` approval. Calls are bounded by count, timeout, request/response size, HTTPS citation validation, and cancellation. The role receives only a structured summary and citation records. Queries, raw provider results, URLs in diagnostics, and provider response bodies never enter normalized events or public logs. Controlled fixtures are verified; real-provider behavior remains pending.

Provider context diagnostics are an implemented private Runtime Host side channel: capability profiles, conservative cache request policy, bounded provider usage, cache eligibility/hit estimates, and compaction records never enter `protocol/schema` or normalized meeting events. Session-frozen long-term memory and Windows-rebuilt normalized-event recovery context are injected into explicitly delimited untrusted private role context. Recovery context is audience-filtered per role and contains bounded recent transcript, constraints, decisions, agenda landmarks, unresolved questions, and sequence ranges; it does not claim to restore Pi private sessions. `RoleContextSnapshotV1` creation, fingerprinting, and validation remain scaffolded, while snapshot persistence/restore, lifecycle-wide invalidation reporting, and the Windows diagnostics UI remain pending. Provider behavior is not `verified` until the recorded real-provider and long-session gates pass.

Run `npm run build` at the repository root, then start the process with `npm run dev:runtime` after setting `PI_ROUNDTABLE_MEETING_ID`; `PI_ROUNDTABLE_RUNTIME_ID`, generation, and working directory remain optional. The supervisor must send one local-protocol-v3 initialize frame containing the validated non-secret workspace profile plus a `credentialRef`-keyed credential map before commands. Role commands carry a normalized frozen participant manifest; the Host resolves private Pi provider/model/prompt/Skill/MCP inputs from those two documents. Credential values stay in process memory and are never included in events, receipts, or diagnostics; MCP environment/header values are materialized only for the approved MCP transport that consumes them. "Zeroized" in this package means only that Pi Roundtable's owned mutable byte buffers were overwritten, never that an immutable JavaScript/SDK/OS string copy was physically erased.

It deliberately does not render a terminal UI. Native applications host this process in the background and translate emitted frames into the normalized meeting protocol.
