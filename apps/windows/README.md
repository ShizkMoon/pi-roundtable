# Windows client

Native C#/WinUI 3 client for the first desktop Runtime Owner. The implemented local client starts the stdio Runtime Host, creates long-term and temporary roles, promotes or archives roles, streams normalized speech events, and supports cancellation, explicit interruption, facilitated agenda/free-discussion/convergence modes, budgeted role floor requests/critical抢答, and automatic anti-loop convergence or pause. A compact adaptive strip exposes the current mode, agenda item, turn/round/interruption budget, queue, and direct host controls without a separate responder selector. The client applies events to the C++ core before changing visible state. A DPAPI-protected SQLite event store persists normalized events and checkpoints so a paused or interrupted live meeting can replay accepted history, reconstruct the scheduler snapshot, and resume under the next `runtimeGeneration`.

The project targets .NET 10 LTS and Windows App SDK 2.3.1. The repository `global.json` pins the verified .NET 10 feature band while allowing servicing patches. The current workstation has the required .NET SDK; WinUI restore/build verification still depends on the installed Visual Studio workloads and package restore.

The implemented first installer target is an x64 MSI containing the .NET runtime, Windows App SDK, Node 24 runtime, Pi Runtime Host, and native meeting core. `scripts/build-windows-x64.ps1` builds and verifies the code, publishes the self-contained WinUI resources, stages production Node dependencies from the reviewed `packaging/windows-runtime/package-lock.json` with `npm ci` and lifecycle scripts disabled, and generates the MSI through WiX 4. Its ICE03 allowlist is a strict gate; suppressing MSI validation is not a verified release path. The payload has automated Authenticode signing hooks, an isolated MSI install/repair/upgrade/downgrade-block/uninstall harness, and strict visual-report aggregation. The desktop updater and independent elevated helper now share `PiRoundtable.Distribution` for bounded byte transfer, immutable size/SHA-256 expectations, fixed-time digest verification, no-follow reparse checks, and a verified file-handle lock; ECDSA manifest trust, redirect rules, Authenticode, process fencing, and install authorization remain in their owning components. Both the compact real-WinUI-shell gate and the complete 22,594-file production payload lifecycle are verified on the current Windows workstation, including responsive launch and zero QA residue; every future release candidate must rerun the gate. The signing mechanics are verified with an ephemeral certificate, while a formally trusted and timestamped release remains pending an external production certificate. A real interactive workstation has verified light, dark, and system high-contrast rendering at 150% DPI across 720/900/1280/1520 DIP; 100%/200% require separate real matching display sessions and cannot be simulated by the process. Provider/model persistence, provider model-list discovery/import, and API-key storage in Windows Credential Manager are implemented. Git Skill/MCP imports use a bounded temporary checkout, a redacted LLM review snapshot, an isolated atomic catalog install, and an explicit disabled-until-approved lifecycle. Interactive MCP tool approval exposes only sanitized server/tool identity to the host; arguments and results remain private. Pi SubAgents are isolated, cannot recurse, expose bounded progress, and return their result only to the parent role. ARM64 native-core packaging and its architecture-matched updater helper remain pending.

For development, build TypeScript and C++ before building/running WinUI. The x64 project copies `out/build/dev/core/pi_roundtable_core.dll` beside the application when it exists. The client locates `packages/runtime-host/dist/host-main.js` by walking to the repository root; source checkout and test overrides are available through `PI_ROUNDTABLE_RUNTIME_HOST_SCRIPT` and `PI_ROUNDTABLE_NODE_PATH`. A packaged build always prefers `runtime/node.exe` and `runtime-host/host-main.js` beside the application and therefore ignores those inherited override variables, so end users do not need Node or the repository checkout.
