# Pi Roundtable v0.4.1 release notes

Status: Windows x64 personal-project alpha.

Pi Roundtable v0.4.1 completes the first Windows local-first meeting workflows.
The shipped product is a self-contained Windows x64 application whose local Pi
Runtime Host owns model execution. Android remains a UI-only scaffold and is
not included in the Windows release assets.

## Highlights

- Windows now connects the local meeting, configuration, session, recovery,
  role-memory, and artifact workflows through the native client.
- Role memory is stored locally with bounded recall context, audience-aware
  recovery, audit records, and retention-job state.
- The local artifact store imports files into content-addressed storage, binds
  them to meetings, verifies hashes during promotion, and cleans orphaned
  temporary content.
- Meeting recovery fails closed when events cannot be projected and only passes
  bounded, audience-filtered context to the Runtime Host.
- Primary roles and subagents can use provider-backed web search when the
  configured provider, capability policy, approval policy, timeout, and result
  limits allow it.
- The Windows meeting database migrates forward from schema v2 to v3 for role
  memory, recall audits, context snapshots, and retention jobs.
- Windows release assets remain commit-bound and include dependency inventory,
  CycloneDX SBOM, third-party notices, and SHA-256 values.

## Release verification

The release candidate is built from a clean exact `main` commit. The required
gate runs the complete repository tests, default MSI ICE validation, and the
full self-contained payload through isolated install, launch, repair, major
upgrade, downgrade blocking, second repair, uninstall, and residue checks. The
publisher re-downloads and hashes the draft, final pre-publication, and public
assets.

This personal release is allowed to be unsigned. Its ECDSA-signed updater
manifest still binds the canonical GitHub URL, file name, size, SHA-256, version,
channel, and architecture. Windows may display an unknown-publisher or
SmartScreen warning when the MSI is opened.

## Compatibility and known limitations

- Public protocol remains v1. The Windows meeting database migrates from schema
  v2 to v3. Existing v0.4.0 data is migrated forward, but a v0.4.0 client cannot
  open a database after that migration; no automatic local-data downgrade is
  provided.
- Provider-backed web search requires an explicitly configured compatible
  provider and policy. A real-provider scenario remains an optional diagnostic
  and is not claimed as verified by the release gate.
- A production-UpgradeCode stable-to-candidate run on a disposable clean VM and
  a real 96/144/192 DPI matrix are optional diagnostics and are not claimed as
  verified for this release.
- Android remote sync, E2EE, TLS termination, rate limits, multi-replica
  notifications, and push remain pending.
- The default sync Compose deployment uses in-memory storage; restarting it
  loses meetings, leases, and replay history.
