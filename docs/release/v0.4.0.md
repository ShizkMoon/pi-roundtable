# Pi Roundtable v0.4.0 release notes

Status: candidate preparation; not published.

Pi Roundtable v0.4.0 is the next Windows local-first alpha. The shipped product remains a self-contained Windows x64 application whose local Pi Runtime Host owns model execution. Android remains a UI-only scaffold and is not part of the Windows release artifact.

## Highlights

- Private tool-approval events now preserve both the direct host and the acting role in their audience, matching the public protocol and deterministic C++ reducer.
- Protocol and sync relay accept syntactically valid additive v1 event kinds. Windows persists the cursor and requires an application upgrade before projecting an event kind that its closed reducer does not understand.
- Windows event ingestion now fails closed on missing or invalid visibility and enforces the public/private audience contract before data reaches the C++ ABI.
- Provider, MCP, and sync endpoints reject credentials, query strings, fragments, non-loopback HTTP, and IPv4-mapped IPv6. HTTPS and canonical localhost, IPv4 `127/8`, and IPv6 `::1` remain accepted.
- The development sync server refuses unauthenticated startup. Docker Compose requires an explicit device-token key map and remains a documented memory-only development deployment unless PostgreSQL is configured separately.
- Shipped Runtime Host dependencies are pinned to patched `undici` 8.9.0 and Hono 4.12.34 resolutions. The Windows runtime lock and NuGet application lock are part of the candidate input.
- Windows builds generate a commit-bound dependency inventory, CycloneDX SBOM, third-party notices, and candidate metadata. The implemented release-owner publisher verifies protected main, candidate hashes, legal materials, the configured production Authenticode signer and timestamp, and both draft and public re-downloaded assets without rewriting the stable v0.3.0 update manifest. A reserved Actions verifier rejects ordinary unsigned CI and remains scaffolded until a production-signed CI producer exists.

## Compatibility and data

- Public protocol version remains v1. Unknown additive event kinds are preserved on the wire but are not interpreted by the current C++ reducer.
- The Windows meeting database remains schema v2. No automatic downgrade of local data is promised.
- The signed stable update manifest remains bound to v0.3.0 until a public v0.4.0 asset has passed the complete release-candidate gate.

## Known limitations and release blockers

- Production-trusted Authenticode signing and RFC 3161 timestamp evidence are pending.
- A clean-VM production v0.3.0-to-v0.4.0 upgrade report is pending.
- Real 96/144/192 DPI evidence bound to the same signed candidate executable is pending.
- Real-provider scenario acceptance and final release-asset/updater offer/no-offer checks are pending.
- The default sync Compose deployment uses in-memory storage; restart loses meetings, leases, and replay history.
- Android remote sync, E2EE, TLS termination, rate limits, retention jobs, and multi-replica notifications remain pending.

The exact evidence state is tracked in the [v0.4.0 release ledger](ledger/v0.4.0.md). Do not publish the release while any required ledger item remains pending.
